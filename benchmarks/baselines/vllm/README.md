# vLLM baseline environment (hosts without Docker)

The vLLM baseline normally runs from the official Docker image pinned by digest (`dli.bench.backends.VLLM_IMAGE`).
Hosts without a Docker daemon (RunPod pods are themselves containers) run the **same release** from this environment:

- `requirements.in`: `vllm==0.32.0`. `requirements.txt` is the hash-pinned lock (198 packages, `torch==2.13.0+cu130`
  from the PyTorch CUDA 13.0 index, as in the image), generated by `scripts/gpu/lock_vllm.sh` with releases cut off at
  2026-10-28 (supply-chain policy) and installed by `scripts/gpu/bootstrap_vllm.sh` with `--require-hashes`.
- It is separate from the project's `uv.lock` because vLLM pins its own torch and dependency versions.

## Accepted risk (recorded 2026-11-11)
`pip-audit` reports PYSEC-2026-3447 / GHSA-xmj3-9gf7-h52w in `setuptools 80.10.2`. The project itself requires
`setuptools>=84.1.0`, but vLLM 0.32.0 requires `setuptools<81`, so the fix cannot be applied here. Scope: this
environment is used only to run the benchmark baseline on a disposable GPU host, installs hash-pinned packages, serves
only on 127.0.0.1, and is never shipped. Re-lock when a vLLM release accepts a fixed setuptools.

The two runtimes are the same vLLM release but not byte-identical builds (image vs wheels), so results record which
launcher ran (`launcher` in each server record); compare vLLM numbers only within one launcher and host.

## Sampler setting on GPUs with more than 16 SMs (recorded 2026-11-11)
vLLM 0.32.0 uses FlashInfer's top-k/top-p sampling kernels only on GPUs with more than 16 SMs. On the A16 (10 SMs) it
logged "FlashInfer top-p/top-k sampling unavailable ... falling back" and used its PyTorch sampler in every M5 run. On
the RTX A5000 (64 SMs) it tries FlashInfer sampling, which in a pip install needs either a CUDA toolkit to JIT-compile
the kernel or FlashInfer's JIT-cache wheel (whose cu130 build depends on Blackwell-only companion wheels). Plans for
the A5000 therefore set `VLLM_USE_FLASHINFER_SAMPLER=0`, vLLM's documented switch: the same sampler as every A16 run,
so the vLLM configuration is identical across GPUs. Attention uses `FLASH_ATTN` on both. Benchmarks decode greedily,
where the sampler is a negligible share of a step. The environment is recorded with each server (`env`).
