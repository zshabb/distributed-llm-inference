# Benchmark methodology

Portfolio-wide rules: `ENGINEERING_STANDARDS.md` §7 (baselines, identical conditions, open-loop load, repetitions,
laptop noise control, profiling evidence, publishing negative results) and §3 (evidence labels and tiers).

Every result directory `benchmarks/results/<UTC date>-<label>-<name>/` contains raw data, an `env.json` whose revision
was captured when the run **started** (untracked files count as dirty), and a summary generated by script. Raw results are
never edited: corrections go in a `PROVENANCE.md` beside them.

## Studies

### M1 greedy parity (correctness, not performance)
`tests/parity/test_hf_greedy_parity.py`: 100 fixed prompts (`tests/parity/prompts.jsonl`, built by `build_prompts.py`)
× 128 greedy tokens, identical token ids for both implementations, no EOS stopping. Labels `[CPU-LAPTOP]` fp32 and
`[GPU:A16x1@vultr]` bf16.

### M2 paged-vs-contiguous spot check (correctness)
`tests/parity/test_paged_parity.py`: 20 completion prompts × 32 tokens on SmolLM2-135M, cold and shared-prefix passes,
block size 16. `[CPU-LAPTOP]`.

### M2 prefix-cache eviction policies `[SIM]`
`benchmarks/scripts/prefix_cache_sim.py`
- **System under test:** the real `BlockManager` (hashing, lookup, allocation, eviction). No model forward passes.
- **Traces** (seeded, 3,000 requests each; token ids uniform in [0, 32000)):
  - *shared-system*: 20 system prompts (200–800 tokens) chosen with Zipf(s=1.1) popularity, + 10–120 unique tokens, 64 decode tokens.
  - *multi-turn*: up to 12 concurrent sessions. Each turn's prompt = full previous context + 20–80 new tokens, then
    30–200 response tokens appended. A session ends with p=0.1 per turn or above 3,000 tokens; new sessions start with
    p=0.15 (Zipf system prompt).
  - *scan-polluted*: multi-turn plus 25% one-off documents (Zipf system prompt + 800–2,400 unique tokens).
- **Procedure:** requests run one at a time (allocate → mark prompt computed → append and compute decode tokens one by one →
  free). Requests that cannot fit in the pool at all are counted as fully computed. Both policies replay the identical
  trace, and differences are reported as paired per-seed deltas over 5 seeds × 4 pool sizes.
- **Metric:** prompt-token hit rate. **Not** latency, TTFT, or throughput.
- **Known biases:** uniform random tokens make unrelated prompts never share content beyond designed prefixes. Sequential
  replay has no concurrent memory pressure from in-flight requests. Synthetic popularity and session distributions.
