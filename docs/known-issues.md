# Known issues and limitations

| # | Issue | Impact | Status / plan |
|---|---|---|---|
| 1 | CI workflows had never run before publication | — | **Resolved** 2026-11-10: first GitHub runs passed (ci: lint, mypy --strict, 95 tests, 54 s; security: full-history gitleaks + pip-audit of both torch builds, 16 s), runs 42907583097 / 42907583166 |
| 2 | `make` is not installed in the WSL2 dev environment (needs `sudo apt install make`, owner action) | `Makefile` targets unusable locally; the underlying `uv run …` commands are used directly | Open |
| 3 | No C compiler in WSL2. Triton's runtime needs one on any machine that JIT-compiles kernels | No impact on CPU paths. The GPU host has gcc and Triton JIT is verified there | Open (laptop only) |
| 4 | M1 generation uses a contiguous per-sequence KV cache and greedy decoding only | Not the serving path; exists for numerical parity. Paged KV (M2) and sampling (M3/M4) replace it | By design |
| 5 | Llama-3.x weights are gated (HF token required, never placed on the GPU host) | The Llama architecture is verified with real SmolLM2 weights (`model_type: llama`), but Llama-3 RoPE scaling only against random-weight reference models | Revisit if the owner approves a token for local use |
| 6 | Provenance bug: `env.json` recorded the revision at write time, not run start | First fp32 CPU parity `env.json` shows a wrong revision; measurement unaffected (verified by `git diff`) | **Fixed** in `46f6359` + regression test; correction in the result's `PROVENANCE.md` |
| 7 | `sync.sh` prints "cannot delete non-empty directory: benchmarks" in HEAD mode | Cosmetic: rsync declines to delete the remote `benchmarks/` because its excluded `results/` subtree is protected | Accepted |
| 8 | `setup_docker.sh` install path (Docker absent) has never run: the Vultr image shipped Docker + toolkit | Rebuild on a different image could hit an unexercised path | Open; exercise on next rebuild |
| 9 | Parity covers prompts ≤ 53 tokens + 128 generated (≤ 181 positions) | Long-context behavior unverified on real weights | Extend in M3 when chunked prefill lands |
| 10 | Complete GPU server recreation has never been performed | Recovery time and the full procedure are unverified; only the user-level bootstrap (25 s) and validation are measured | Open; perform and time on the next approved rebuild (operations.md §4) |
| 11 | Process deviation: M0–M1 were committed directly to `main` instead of a feature branch with a `--no-ff` merge | Review record is the commit history itself rather than a merge commit | Branch workflow applies from M2 |
| 12 | Paged KV read path gathers the whole prefix per layer per decode step | Paged decoding is slower than the contiguous cache on CPU (correctness reference only) | By design until the M6 Triton paged-attention kernel reads pages in place |
| 13 | Prefix sharing is block-granular (16 tokens by default) | Prefixes shorter than a block, and the partial tail of longer ones, are not shared | Accepted (ADR-0003); radix/partial-block sharing is a possible extension |
| 14 | Identical prompts admitted before either is computed keep private copies | Temporary duplicate memory (counted in `duplicate_registrations`) | Accepted; merge-on-register is a possible optimization |
| 15 | Eviction-policy results are trace simulations of hit rate only | No latency/TTFT evidence for the policies yet | Measure with the engine in M3/M5 |
| 16 | Admission scans the waiting queue with `min()`: O(W) per admitted request | Measured negligible at W = 512 (0.04 s per 512 admissions); would matter at ~10^4 queued requests | Open; per-tenant queues + a heap over tenants when profiling shows it |
| 17 | Preemption is recompute-only (no swap to host memory) | Preempted work is recomputed, partly recovered by prefix-cache hits | Swap needs GPU measurements of PCIe vs recompute cost; revisit with M6/M10 |
| 18 | Engine loop is single-threaded and synchronous | Cancellation takes effect between steps (at most one step of wasted work) | **Resolved for serving** in M4: `AsyncEngine` runs the loop on a dedicated thread behind a command queue; the loop itself stays synchronous by design |
| 19 | Requests admitted in the same step cannot share a prefix | Concurrent identical prompts compute duplicate KV | By design (blocks are shareable only after compute, ADR-0003); see also #14 |
| 20 | Batched attention is a per-segment Python loop | Attention cost grows with the number of sequences per step on the CPU reference path | Replaced by the M6 Triton varlen paged kernel |
| 21 | Engine-overhead absolute values vary ~2x between laptop runs | Only the flat per-sequence shape is claimed, not absolute microseconds | Inherent to the 15 W laptop CPU; re-measure on the GPU host / in M5 |
| 22 | Published commit `207083c` contains absolute paths revealing the local username (`/home/<user>/src/distributed-llm-inference/...`) in cProfile output | **Low severity, accepted.** Verified 2026-11-10: only the username and the repository directory layout; no credentials, keys, hosts, or other secrets (pattern scan + gitleaks on the commit); no other published commit affected | **Closed: owner decided to keep history** (no rewrite/force-push). Redaction in `scheduler_overhead.py` and the pre-push personal-path grep remain in place |
| 23 | OpenAI features outside contract C1: `n` > 1, `best_of`, `logprobs`, presence/frequency penalties ≠ 0, `logit_bias`, `echo`, `suffix`, tools/functions, `response_format` | Rejected with 400 `unsupported_parameter` (never silently ignored) | By design for M4; add when a consumer needs them |
| 24 | One model per process, plain HTTP | No TLS or multi-model routing in the server | TLS terminates at the router/ingress (M8/M9); one model per worker is the deployment unit |
| 25 | API keys are read at startup | Adding or revoking a key needs a restart (drain makes this lossless) | Open; hot reload when a key-management story exists |
| 26 | Admission predicts time to first token from queued prefill tokens and a prefill-rate EWMA only | Ignores decode contention and preemption, so it under-predicts under heavy decode load; no per-tenant rate limits (the scheduler provides weighted fairness, not quotas) | Calibrate against measured TTFT in M5; quotas belong in the router (M8) |
| 27 | Server-side latency/throughput under load is not measured | M4 tests prove behaviour, not performance; HTTP + detokenization overhead is unquantified | M5 benchmark harness (open-loop load, TTFT/ITL percentiles) |
| 28 | Client disconnect is noticed when the next chunk is written | A client that disappears while its request is still queued is detected when the first token arrives (KV is freed then) | Accepted; a polling disconnect watcher is possible if queues grow long |
| 29 | bf16 output depends on batch composition | The same greedy request can give different tokens depending on which requests share its batch (M3; seen again over HTTP in M4, where streamed and non-streamed copies of a prompt differed for 13/24 and 9/24 prompts, all at near-ties) | Open. fp32 is exact; bf16 quality is evaluated in M5. Batch-invariant decoding (fixed reduction order) is a possible later option, not planned |
